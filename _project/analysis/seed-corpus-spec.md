## Purpose and Motivation

The results explorer (`benchbox.dev/results/`) is a dynamic comparison tool: visitors
pick a benchmark, scale factor, and platforms to build cross-platform query-level
comparisons. That tool is only useful if the corpus has **depth** — multiple comparable
platforms at the same benchmark × scale factor — not just breadth across many isolated
runs.

The seed corpus provides that depth at launch. It is the minimum viable dataset that
makes the compare view meaningful from day one, without waiting for community
contributions (Phase 2) or a hosted API (Phase 3).

**Primary constraint:** each benchmark × scale factor cohort must have ≥3 platforms so
the compare view can show a real cross-platform ranking. A cohort with two platforms is
a pair; three is the minimum for a meaningful spread.

**Secondary constraint:** all seed corpus results use the `maintainer-run` trust label
(`public-curated` visibility). They are generated by the BenchBox CI via the
`seed-corpus.yml` workflow, not submitted by external contributors.

## Platform and Benchmark Notes

### TPC-DS: Integer-Only Scale Factors

TPC-DS `dsdgen` does not support fractional scale factors. Valid values are integers:
1, 2, 3, 10, 30, 100, 300, 1000, etc. The seed corpus uses SF 1 (smallest valid
integer). **Do not attempt SF 0.01 or SF 0.1 for TPC-DS** — these will produce
malformed or empty data sets.

### DataFusion: Query Subset Limitations

DataFusion does not support the full TPC-H and TPC-DS query sets due to SQL dialect
gaps (certain correlated subqueries, window function variants). The generated bundle
will contain results only for the queries that ran successfully. The explorer treats
partial-query bundles as valid but includes a `query_subset: true` flag in the manifest
so the compare view can surface a warning when comparing a full run against a partial
run.

The seed corpus does **not** use `--queries` to pre-filter — the full benchmark is
attempted and the exporter records which queries passed and which failed.

### ClickHouse Cloud: Conditional on Availability

ClickHouse Cloud requires external credentials (`CLICKHOUSE_HOST`, `CLICKHOUSE_PASSWORD`
secrets). The SF 1.0 TPC-H matrix entry for ClickHouse Cloud is skipped if those
secrets are absent. The workflow uses `continue-on-error: true` for this entry and
the `create-pr` job collects whatever artifacts were produced.

### polars-df: DataFrame Mode Platforms

`polars-df` is a DataFrame-mode platform. DataFrame and SQL results can coexist in the
same cohort at the compare view level only when the benchmark supports both modes (TPC-H
and SSB do; TPC-DS does not have a DataFrame adapter). The explorer marks the execution
mode in the manifest so users can filter by mode.

### Phases

All seed corpus runs use `--phases generate,load,power`. The `throughput` and
`maintenance` phases are excluded to keep CI run time reasonable. The `power` phase
is the standard single-stream timing that drives the compare view.

## Storage Layout

```
results-data/
  bundles/
    {benchmark}/
      {platform}/
        sf{scale_factor}/
          {run_id}.json            # primary result bundle (schema-v2)
          {run_id}.plans.json      # query plans (if captured)
          {run_id}.tuning.json     # tuning config applied (if any)
```

Examples:
- `results-data/bundles/tpch/duckdb/sf0.01/tpch-duckdb-sf0.01-20260402.json`
- `results-data/bundles/tpch/datafusion/sf1.0/tpch-datafusion-sf1.0-20260402.json`
- `results-data/bundles/tpcds/duckdb/sf1/tpcds-duckdb-sf1-20260402.json`
- `results-data/bundles/ssb/polars-df/sf0.1/ssb-polars-df-sf0.1-20260402.json`

Scale factor in path uses the raw value passed to `--scale`:
- `0.01` → `sf0.01`
- `0.1` → `sf0.1`
- `1.0` or `1` → `sf1.0` (TPC-H/SSB) or `sf1` (TPC-DS, integer-only)

## Refresh Cadence

| Trigger | Condition |
|---------|-----------|
| `workflow_dispatch` | Manual trigger — run on demand to refresh or add bundles |
| Scheduled (quarterly) | Cron: first Monday of each quarter — keeps corpus current as platform versions evolve |

The quarterly schedule ensures that seed corpus results do not become stale as DuckDB,
DataFusion, and other platforms release new versions. Each scheduled run opens a PR
with updated bundles; a maintainer reviews and merges.

## Trust and Visibility

| Field | Value |
|-------|-------|
| Trust label | `maintainer-run` |
| Visibility | `public-curated` |
| Attribution | BenchBox CI (`benchbox-bot`) |
| Reproducibility | Any bundle can be re-run with `benchbox run` using the same parameters recorded in the bundle metadata |

Phase 1 does not implement a full trust tier system. All results in `results-data/` at
launch are maintainer-curated. The `maintainer-run` + `public-curated` labels are
recorded in the bundle manifest so the Phase 2 PR-based contribution workflow can
introduce the `community` trust tier without a breaking schema change.
